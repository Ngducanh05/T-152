# ParkSmart canonical parking-map specification

## Authority and scope

This specification describes the current F1/F2/F3 map generated by
`src/core/parking_map.py`. It supersedes the historical one-floor map in the original
two-week implementation guide wherever the two documents conflict.

The same canonical graph is used by routing, recommendations, seed data, the existing
`ParkingMap` flat renderer and the existing `IsometricMap` renderer. A new renderer must
not be introduced for floor support.

## Identifier rules

- Floor IDs are `F1`, `F2` and `F3`.
- Slot IDs use `{floor}-{zone}{number}`, for example `F2-D03`.
- Zones are `A`, `B`, `C` and `D`; numbers are `01` through `10`.
- Aisle nodes use `{floor}-{zone}-{side}`, where side is `W` or `E`.
- Shared node IDs include `{floor}-CP1`, `{floor}-CP2`, `{floor}-CP3`,
  `{floor}-ELEVATOR` and `{floor}-RAMP`.
- `F1-ENTRANCE` and `F1-EXIT` are the only vehicle entrance and exit.

Every slot, its aisle node and its floor must have matching prefixes.

## Canonical inventory

| Item | F1 | F2 | F3 | Total |
|---|---:|---:|---:|---:|
| Parking slots | 40 | 40 | 40 | 120 |
| EV slots | 10 | 10 | 10 | 30 |
| Checkpoints | 3 | 3 | 3 | 9 |
| Elevator nodes | 1 | 1 | 1 | 3 |
| Ramp nodes | 1 | 1 | 1 | 3 |
| Map nodes | 55 | 53 | 53 | 161 |

Within-floor edges total 59 on F1 and 57 on each upper floor. Four inter-floor edges
connect adjacent floors through the ramp and elevator, for 177 edges in total.

Each floor contains ten slots per zone. EV charging is available at `C01`–`C05` and
`D01`–`D05` on every floor. The remaining slots are standard slots.

## Graph and cross-floor routing

- All slot nodes connect to their assigned aisle node.
- Each floor has the CP1–CP2–CP3 road spine and the four zone aisle branches.
- The elevator connects to the inner C/D aisles on its floor.
- The ramp is part of the road graph and connects each adjacent floor pair.
- Elevator and ramp links connect F1↔F2 and F2↔F3; there is no direct F1↔F3 edge.
- Cross-floor routing must use the graph and real edge distance, not a fabricated floor
  penalty or LLM interpretation.

## Floor-aware recommendations

`RecommendationRequest.floor_id` is optional. When supplied, it is a hard filter and only
slots from that floor may be returned. `zone_id` is independently optional. When no floor
is supplied, candidates across all floors are ranked using real route distance and the
requested charging, accessibility and elevator preferences.

## Adjacent-slot observations

Physical adjacency is derived identically in backend and frontend:

- same floor;
- same zone;
- same five-slot row (`01`–`05` or `06`–`10`);
- immediate numeric neighbour only;
- never wrap between `05` and `06` and never cross floors.

Examples:

- `F2-D03` → `F2-D02`, `F2-D04`;
- `F3-A05` → `F3-A04`;
- `F1-B06` → `F1-B07`;
- `F4-A01` is invalid.

## Rendering contract

- Floor tabs select F1, F2 or F3 in both existing map views.
- `ParkingMap` renders the flat plan; `IsometricMap` renders the basement perspective.
- Isometric occupancy uses a rectangular three-face vehicle block.
- The isometric view is fixed and has no drag-to-rotate interaction.
- Ramp/up/down blocks use the road palette, sit beside the driving lane and use longitudinal
  white markings; the down ramp includes a visible tunnel opening.
- OPEN report overlays keep a red warning border/icon.
- PENDING observation overlays keep an amber verification border/icon.
- Selection adds a blue outline/glow without replacing the slot status colour.
- Overlay meaning must also be exposed by icon, badge and accessible label, not colour alone.

## Seed and verification

Run the canonical idempotent seed after migrations:

```powershell
uv run python scripts\seed_demo.py
uv run python scripts\seed_demo.py
```

The second run must not create duplicates. On a complete database, verify:

```text
parking_slots: F1=40, F2=40, F3=40, total=120
map_nodes:     F1=55, F2=53, F3=53, total=161
map_edges:     total=177
```

Do not treat a database containing only the original 40 F1 slots as a valid multi-floor
seed, even if the application code can generate F2/F3 in memory.
